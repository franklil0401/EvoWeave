# 命令行使用

## 命令总览

```text
evoweave init [仓库]
evoweave analyze [仓库] --request 需求 [--path 允许路径] [--image 图片]
evoweave run [仓库] --request 需求 --path 允许路径 [--execute] [--approve-high-risk]
evoweave resume [仓库] RUN_ID [--execute] [--approve-high-risk]
evoweave status [仓库] [--run-id RUN_ID]
evoweave export [仓库] RUN_ID [--output 目录]
evoweave models doctor [--network]
```

所有命令均可使用 `--json` 输出稳定 JSON 信封。失败时返回非零退出码，并提供稳定错误码和不包含密钥的简短信息。

## 安全预检与执行

不带 `--execute` 的 `run` 会完成以下动作：

1. 固定目标仓库当前 commit；
2. 校验请求、允许/禁止路径和图片；
3. 创建内容寻址产物库和运行清单；
4. 生成只读仓库画像；
5. 保存 `analyzed` 状态供后续恢复。

带 `--execute` 时，系统先根据允许路径、固定 commit 代码规模和模块依赖生成任务数与 DAG。高风险请求先等待人工批准；其余请求再检查验证沙箱和模型列表。独立就绪任务获得不同的 Agent、模型路由、能力和 worktree，并可真实并发运行；依赖任务分批运行。全部补丁经过独立集成 worktree 和四级确定性门禁。系统只输出补丁，不写主分支，也不自动 push。

## 恢复

`resume` 默认只读取持久状态；对 `analyzed` 或 `waiting_for_input` 运行增加 `--execute` 可继续。高风险运行还必须增加 `--approve-high-risk`。已完成和失败运行是终态，不会被静默重放。

当前检查点可恢复任务图、分配、执行规格和决策账本。若进程恰好在单个 Worker 的模型步骤中被强制终止，系统可定位该步骤，但阶段 6 尚不承诺逐 Token 无重复续传；恢复前应先用 `status` 和导出报告审查状态。

## 动态模型回退

CLI 的 `--model` 是首选优先级，不会绕过任务能力要求。首选模型在执行中不可用、返回能力不匹配或无效结构时，总调度按运行前记录的候选链创建新的 Agent 与更高版本 `AgentExecutionSpec`；旧失败结果和路由决策保留在检查点及事件中。
