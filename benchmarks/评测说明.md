# EvoWeave 基准评测说明

> 任务集版本：`evoweave_v1` v3
> 当前证据状态：隐藏验收、规划审计和真实运行器已完成；正式效果矩阵待运行

## 1. 评测问题

评测不只回答“系统能不能运行”，而要分别回答：

1. 动态 Agent 是否比单 Agent、固定四步多 Agent 更有效；
2. 动态选模是否比固定低档或固定高档模型更合适；
3. 动态方案是否减少无效实例、冲突、总调度上下文和不必要的图片暴露；
4. 动态方案在哪些任务上没有收益或会失败。

## 2. 冻结任务集

`任务集/第一版任务集.json` 固定 12 个任务，覆盖单文件、单模块、串行多模块、并行多模块、低定位置信度、基线失败、写冲突、高风险、两个图片相关任务、图片负例和模型回退。

每项任务固定以下信息：

- fixture 内容 SHA-256 和确定性 Git commit；
- 用户目标、验收条件和允许/禁止路径；
- 图片内容 SHA-256、MIME 和任务是否实际需要图片；
- 人工难度、所需模态、人工标注修改点和回归命令；
- 基线通过或失败状态和场景标签。
- 独立隐藏验收脚本及其内容 SHA-256。

任务集文件本身也计算 SHA-256。修改任何标签、需求或路径都会得到新摘要，旧结果不能与新任务集混用。

## 3. 对照矩阵

Agent 策略：

- `single_agent`：一个通用实例负责全部授权写范围；
- `fixed_multi_agent`：固定四个串行通用实例，执行探索、实现、审查、验证步骤；
- `adaptive_agent`：按写范围、代码规模、模块依赖、风险和图片相关性生成任务图。

模型策略：

- `fixed_low`：使用一个满足硬约束的固定低档候选；
- `fixed_high`：使用一个满足硬约束的固定高档候选；
- `adaptive_model`：根据难度、模态、上下文、工具和结构化输出要求路由。

完整效果矩阵在同一真实性等级下包含 `12 × 3 × 3 = 108` 条唯一运行记录。缺少任一组合时，报告保持 `PENDING`，不得把缺失数据填成零。

## 4. 真实性等级

| 等级 | 含义 | 可以支持的结论 |
|---|---|---|
| `offline_replay` | 脚本化模型或历史响应的确定性重放 | 协议、计量和报告逻辑正确 |
| `live_model` | 锁定模型 ID、参数和能力快照的真实 API 调用 | 当前模型快照下的实际效果 |
| 规划审计 | 不调用模型，只运行真实仓库画像与任务规划器 | Agent 数、DAG、难度、风险和图片暴露 |

规划审计不属于成功率实验，离线重放也不能冒充真实模型结论。

## 5. 当前可复现命令

```powershell
uv run --no-editable evoweave benchmark validate `
  --suite benchmarks/任务集/第一版任务集.json `
  --project-root .

uv run --no-editable evoweave benchmark audit `
  --suite benchmarks/任务集/第一版任务集.json `
  --project-root . `
  --output benchmarks/结果

uv run --no-editable evoweave benchmark summarize `
  --suite benchmarks/任务集/第一版任务集.json `
  --results benchmarks/结果/结果模板.json `
  --output benchmarks/结果

uv run --no-editable evoweave benchmark run `
  --suite benchmarks/任务集/第一版任务集.json `
  --project-root . `
  --results benchmarks/结果/真实模型结果.json
```

`validate` 校验 fixture、commit、图片和隐藏验收摘要；`audit` 产生规划审计；`run` 调用当前账号已发现的真实模型并逐条原子保存结果与证据；`summarize` 只聚合已有运行记录。当前正式结果为空，因此效果汇总必须显示待运行。

## 6. 指标与防作弊规则

核心指标包括任务成功率、定位召回率、补丁有效率、回归率、总 Token、墙钟时延、Agent 数、无效任务率、冲突率、总调度/Worker 上下文量、首次路由有效率、回退率、难度匹配率和图片暴露数。

评测必须遵守：

- 三种策略使用同一个任务 commit、允许路径、运行上限和确定性验收；
- 目标测试与全量回归同时通过才算任务成功；
- 补丁越权、未应用或未授权不能记为通过；
- 运行失败必须记录结构化原因，不能删除失败样本；
- 同一报告中的记录必须绑定同一个任务集 SHA-256 和同一个系统 Git commit；
- 不按费用或预算选择模型；
- API Key 值、完整私有推理和未脱敏源码不得进入结果文件；
- 每项隐藏验收都必须证明原始基线失败、已知正确实现通过；fixture 自带 Pytest 只承担回归检查，不能替代需求验收。
- 模型回退场景必须注入一次可审计的首选模型不可用故障，并验证新版 Agent/执行规格和路由确实产生；图片正例/负例同时接受系统级原图暴露检查。

## 7. 当前结果

[规划审计报告](结果/规划审计报告.md)已经完成 36 条规划记录。动态策略的冻结人工难度匹配为 12/12；平均创建 1.33 个实例；两个图片相关任务共向 2 个动态 Agent 暴露原图；图片负例暴露为 0。

这些数字只描述规划行为。第二版任务集曾执行 12 条动态策略真实调用，其中 4 条通过；随后发现任务 11 的隐藏验收错误导入了其他 fixture 的模块。第三版在系统提交 `4a9b867` 上又完成 12 条探索运行，其中 5 条通过，但任务 12 没有实际触发模型回退，运行器却只按最终代码判为通过，暴露了系统级验收缺口。两轮记录、汇总和证据均完整移入 `结果/已废弃/`，不能作为正式成功率。当前已补故障注入与结构验收，仍需在新提交上重跑；完整 108 条矩阵前不形成 Go/No-Go 结论。
