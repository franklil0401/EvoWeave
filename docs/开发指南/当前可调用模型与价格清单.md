# EvoWeave 当前可调用模型与价格清单

> 文档性质：模型能力、输入模态、上下文、价格资料与真实调用基线
> 当前版本：0.3
> 数据日期：2026-08-13  
> 适用范围：DeepSeek、火山方舟豆包、阿里云百炼千问
> 安全要求：只记录模型元数据和脱敏测试结果，不记录 API Key

## 1. 当前结论

EvoWeave 不再维护豆包和千问的完整模型目录，而是每家只保留三款经过当前账号实测的模型。选择顺序优先考虑：

1. 当前账号能够真实调用；
2. 尽量使用最新稳定模型或最新滚动别名；
3. 同一厂家形成高、中、低三个能力档位；
4. 三家模型整体覆盖文本和多模态输入；
5. 适合 Agent、长上下文、工具调用和软件仓库分析。

| 厂家 | 高档 | 中档 | 低档 | 当前账号实测 |
|---|---|---|---|---|
| DeepSeek | `deepseek-v4-pro` | — | `deepseek-v4-flash` | Flash 文本成功；Pro 目录可见，尚未付费实测 |
| 豆包 | `doubao-seed-evolving` | `doubao-seed-2-1-turbo-260628` | `doubao-seed-2-0-mini-260428` | 三款文本和图片输入全部成功 |
| 千问 | `qwen3.8-max` | `qwen3.7-plus` | `qwen3.7-flash` | 三款文本成功；Plus、Flash 图片输入成功 |

“API 可发现”只表示模型出现在模型列表接口中；“实测成功”才表示当前 Key、端点、地域和账号权限确实可以完成推理。可用性和价格会变化，运行时仍须重新探测。

本文件保留用户要求的公开价格资料，但价格、费用和优惠不进入 EvoWeave 的 `ModelRequirement`、`ModelProfile` 或 `ModelRouter`。运行时路由只使用任务难度、输入模态、上下文、所需能力、可用状态和稳定优先级。

## 2. 价格与参数说明

- 表中价格是中国大陆公开按量原价，币种为人民币，不含活动折扣、免费额度、Batch、Token Plan、资源包和缓存折扣；
- “输入/输出价格”均以每百万 Token 为单位；
- 阶梯价格由单次请求的输入 Token 总量决定；
- 厂商没有公开闭源模型的权重参数量时统一写“未公开”，不能用上下文窗口冒充参数规模；
- 图片、音频和视频会由厂商转换或折算为 Token，实际费用不能只根据文件大小估算；
- 最终账单以对应地域控制台为准。

DeepSeek 当前模型列表只有两款，因此不人为凑够三款。两款均以文本为原生输入，不支持直接传入图片、音频或视频；EvoWeave 的多模态覆盖由豆包和千问承担。

| 档位 | 模型 ID | 输入 → 输出 | 上下文 / 最大输出 | 参数规模 | 公开价格（美元/百万 Token） | 当前状态 |
|---|---|---|---:|---|---|---|
| 高档 | `deepseek-v4-pro` | 文本 → 文本/工具调用 | 1M / 384K | 1.6T 总参数，49B 激活 | 命中输入 $0.003625；未命中输入 $0.435；输出 $0.87 | API 可发现，未付费实测 |

| 中档 | `doubao-seed-2-1-turbo-260628` | 文本、图片、视频 → 文本 | 256K / 256K | 未公开 | 输入 ¥3；输出 ¥15 | 文本、图片实测成功 |
| 低档 | `doubao-seed-2-0-mini-260428` | 文本、图片、视频、音频 → 文本 | 256K / 128K | 未公开 | 输入 ¥0.2 起；输出 ¥2 起 | 文本、图片实测成功；音频未实测 |

价格来自[火山引擎豆包产品页](https://www.volcengine.com/product/doubao)。Mini 的公开页面使用“起”字，表示还存在输入长度阶梯；这些价格只作为人工资料，不进入路由配置。

### 4.2 选择理由

- `doubao-seed-evolving` 是面向 Agent 与 Coding 持续升级的滚动别名，具备 1M 上下文，适合作为复杂仓库分析和长程任务候选；
- `doubao-seed-2-1-turbo-260628` 是当前账号可用的较新中档模型；
- `doubao-seed-2-0-mini-260428` 是当前目录中比 `260215` 更新的 Mini 快照，并额外声明音频输入能力，适合低难度任务；
- 没有选择目录中的其他 Pro、Lite 和 Code Preview 候选，因为当前账号调用均返回 `ModelNotOpen`；文档只保留实际可用的三款。

### 4.3 真实调用结果

文本测试问题统一为：`只回答数字：7乘以6等于多少？`。测试关闭思考模式，限制最大输出为 32 Token。

| 模型 | HTTP | 答案 | 输入/输出/总 Token | 本次端到端时延 |
|---|---:|---:|---:|---:|
| `doubao-seed-evolving` | 200 | `42` | 55 / 2 / 57 | 968 ms |
| `doubao-seed-2-1-turbo-260628` | 200 | `42` | 55 / 2 / 57 | 1,986 ms |
| `doubao-seed-2-0-mini-260428` | 200 | `42` | 39 / 2 / 41 | 771 ms |

图片测试使用程序在内存中生成的白底黑字 `42` PNG，要求模型只返回图片中最醒目的数字。测试图片没有写入仓库。

| 模型 | HTTP | 识别结果 | 输入/输出/总 Token | 本次端到端时延 |
|---|---:|---:|---:|---:|
| `doubao-seed-evolving` | 200 | `42` | 1,334 / 2 / 1,336 | 1,396 ms |
| `doubao-seed-2-1-turbo-260628` | 200 | `42` | 1,334 / 2 / 1,336 | 2,374 ms |
| `doubao-seed-2-0-mini-260428` | 200 | `42` | 1,318 / 2 / 1,320 | 671 ms |

时延只代表本次网络和账号环境，不是正式性能基准。图片即使尺寸很小也消耗了约 1,300 输入 Token，后续需要把视觉 Token 和时延作为资源统计记录，但不用于按价格选模。

下表按北京地域公开输入/输出原价从高到低排列。三款均支持 1M 上下文、思考模式、Function Calling、内置工具和结构化输出。

| 档位 | 模型 ID | 输入 → 输出 | 上下文 | 参数规模 | 北京按量原价（人民币/百万 Token） | 当前状态 |
|---|---|---|---:|---|---|---|
| 高档 | `qwen3.8-max` | 文本 → 文本 | 1M | 未公开 | 输入 ¥12；输出 ¥36 | 文本实测成功 |
| 中档 | `qwen3.7-plus` | 文本、图片、视频 → 文本 | 1M | 未公开 | ≤256K：输入 ¥2、输出 ¥8；>256K：输入 ¥6、输出 ¥24 | 文本、图片实测成功 |
| 低档 | `qwen3.7-flash` | 文本、图片、视频 → 文本 | 1M | 未公开 | ≤32K：¥0.2/¥0.8；32K–256K：¥0.6/¥2.4；256K–1M：¥1.2/¥4.8 | 文本、图片实测成功 |

价格来自[阿里云百炼模型价格页](https://help.aliyun.com/zh/model-studio/model-pricing)，能力与官方推荐来自[千问文本生成模型页](https://help.aliyun.com/zh/model-studio/text-generation-model)。本文使用稳定别名；其中 `qwen3.7-plus` 当前对应 `2026-05-26` 快照，`qwen3.7-flash` 当前对应 `2026-07-15` 快照。

### 5.2 选择理由

- `qwen3.8-max` 是当前最新高能力按量模型，官方推荐用于最强推理任务；
- `qwen3.7-plus` 是官方针对 Agent 和大型代码库推荐的平衡档，具备完整工具调用与 1M 上下文；
- `qwen3.7-flash` 是最新低档模型，且本次文本、图片时延都最短；
- 筛选过程中还验证过上一代 Max，调用成功，但官方已将其列入旧版模型，因此文档不再记录其精确 ID；
- Coder、VL、Omni、图像生成、语音和向量模型不再逐项记录。需要专项模态时由运行时模型发现功能临时选择，避免文档退化为庞大目录。

### 5.3 真实调用结果

文本测试与豆包使用同一问题，并关闭思考模式。

| 模型 | HTTP | 答案 | 输入/输出/总 Token | 本次端到端时延 |
|---|---:|---:|---:|---:|
| `qwen3.8-max` | 200 | `42` | 35 / 2 / 37 | 7,264 ms |
| `qwen3.7-plus` | 200 | `42` | 22 / 2 / 24 | 1,318 ms |
| `qwen3.7-flash` | 200 | `42` | 22 / 2 / 24 | 470 ms |

`qwen3.8-max` 是文本模型，因此未发送图片。Plus 和 Flash 使用与豆包完全相同的内存 PNG 进行图片识别测试。

| 模型 | HTTP | 识别结果 | 输入/输出/总 Token | 本次端到端时延 |
|---|---:|---:|---:|---:|
| `qwen3.7-plus` | 200 | `42` | 97 / 3 / 100 | 1,079 ms |
| `qwen3.7-flash` | 200 | `42` | 97 / 3 / 100 | 637 ms |

同一张测试图在千问侧计 97 输入 Token，在豆包侧约计 1,300 输入 Token。这不代表千问在所有视觉任务中一定更强；该差异只进入 Token 和时延统计，不进入基于价格的模型选择。

## 6. EvoWeave 初始路由建议

| 任务需求 | 首选 | 备选 | 路由理由 |
|---|---|---|---|
| 高难度规划、架构推演 | `qwen3.8-max` | `deepseek-v4-pro`、`doubao-seed-evolving` | 优先强推理；调用频率低 |
| 大型仓库与长程 Agent | `doubao-seed-evolving`、`qwen3.7-plus` | `deepseek-v4-flash` | 1M 上下文和工具能力 |
| 普通代码分析与工具循环 | `qwen3.7-plus`、`doubao-seed-2-1-turbo-260628` | `deepseek-v4-flash` | 中档能力、上下文和工具调用支持 |
| 低难度 Worker | `qwen3.7-flash`、`doubao-seed-2-0-mini-260428` | `deepseek-v4-flash` | 满足低难度要求且实测可用 |
| 截图、界面或架构图理解 | `qwen3.7-plus`、`qwen3.7-flash` | 三款豆包模型 | 当前账号图片输入全部实测通过 |
| 音频需求 | `doubao-seed-2-0-mini-260428` | 专项语音模型 | 目录声明支持音频，但使用前仍需专项实测 |

模型具备 Function Calling 只表示能够生成工具调用意图，不代表 Agent 自动获得文件、终端或网络权限。实际工具必须继续经过 EvoWeave 的任务契约和权限策略。

## 7. 测试边界

本轮只验证了：

- API Key、Base URL 和模型授权；
- 最小文本问答；
- 图片输入与基础视觉识别；
- 响应 Token 用量和单次端到端时延。

本轮没有验证：

- 视频与音频输入质量；
- 长上下文稳定性；
- Function Calling、JSON Schema 和多轮工具循环；
- 代码生成质量、补丁正确性和安全性；
- 并发、限流、缓存命中和正式吞吐；
- 六款模型在 EvoWeave 基准集上的真实胜率。

因此“可用”只表示接口连通和基础能力通过，不能等价为“适合直接承担高风险软件修改”。

## 8. 更新规则

1. 每次发布前通过三家模型列表接口重新确认模型 ID；
2. 豆包和千问的正式清单各保持三款，替换时必须写明理由；
3. 只有真实调用成功的模型才能标记为“实测成功”；
4. 多模态模型至少完成一次图片输入探测，音频和视频按任务需要专项探测；
5. 价格至少每月核对一次，并记录币种、地域、阶梯和查询日期；
6. 厂商未公开参数量时保持“未公开”；
7. 每次运行记录供应商、模型 ID、思考模式、Token、时延和失败切换原因；
8. 不在文档、日志或测试产物中记录 API Key、Authorization Header 或完整敏感请求。
