# 运行结果解读

每次运行在目标仓库 `.runtime/` 下保存：

```text
.runtime/
├─ state/          # run、Worker、集成状态和 SQLite 检查点
├─ artifacts/      # SHA-256 分片内容与强类型引用元数据
├─ worktrees/      # 临时 Worker、基线和集成 worktree
├─ events/         # 每个 run 的追加式 JSONL 事件
└─ reports/        # 中文 Markdown 和机器 JSON 报告
```

状态含义：

- `initialized`：ChangeSpec 已冻结；
- `analyzed`：固定 commit 仓库画像已生成，可继续执行；
- `running`：Worker、集成或验证正在运行；
- `waiting_for_input`：缺少必须由用户提供的安全选择；
- `completed`：最终补丁和验证报告均存在且门禁通过；
- `failed`：终态失败，报告包含稳定错误码。

`completed` 不表示代码已经写入用户分支，只表示候选补丁通过 EvoWeave 的既定门禁。用户仍需审查最终 diff，再自行决定是否应用或提交。

导出的机器 JSON 在运行清单字段之外包含 `orchestration`：其中可查看任务规格、依赖图、动态分配记录、每个 Agent 的模型路由、能力范围、运行上限、结果摘要和最终检查点。模型回退会表现为同一任务对应多个不可变执行规格与不同 Agent ID。

验证报告把失败分为：已有失败、新增回归、已修复失败和不稳定失败。只有新增回归和不稳定失败都不存在，且命令没有超时、截断或基础设施错误时，候选才会被接受。
