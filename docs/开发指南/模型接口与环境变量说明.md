# EvoWeave 模型接口与环境变量说明

> 文档性质：模型供应商接入、环境变量和模型能力的当前技术基线  
> 当前版本：0.5
> 调研日期：2026-08-13  
> 安全要求：本文档只记录变量名和配置方法，禁止写入任何 API Key 值

## 1. 技术结论

EvoWeave 第一版应通过统一 `ModelGateway` 接入 DeepSeek、火山方舟豆包和阿里云百炼千问，不让业务层直接依赖某一家 SDK。三家当前都提供 OpenAI 兼容接入，因此首版可以复用 `openai` Python SDK，但必须保留供应商专属参数、端点和能力探测。

推荐的初始模型分工是：

| 使用场景 | 首选候选 | 备选候选 | 选择理由 |
|---|---|---|---|
| 总调度的复杂拆分与重新规划 | `qwen3.8-max` 或 `doubao-seed-evolving` | `deepseek-v4-pro` | 强推理和长程任务能力优先，调用频率相对较低 |
| 普通临时 Agent 的工具循环 | `qwen3.7-plus` 或 `doubao-seed-2-1-turbo-260628` | `deepseek-v4-flash` | 工具调用、上下文和响应速度平衡 |
| 低难度文本任务 | `qwen3.7-flash` 或 `doubao-seed-2-0-mini-260428` | `deepseek-v4-flash` | 当前账号实测可用，并满足低难度任务能力要求 |
| 图片、截图和架构图理解 | `qwen3.7-plus` 或 `qwen3.7-flash` | 三款已选豆包模型 | 当前账号图片输入实测通过 |

这是 EvoWeave 的工程建议，不代表模型厂商的排行榜结论。最终默认模型必须通过项目基准集确定，不能只根据宣传描述选择。

模型名称、能力和地域会变化。系统启动时应执行模型可用性检查，并把实际供应商、模型 ID、端点类型和能力快照写入运行记录；禁止把本文件列出的模型永久硬编码为唯一可用模型。价格清单仅供人工查阅，不进入 `ModelRouter` 的输入。

## 2. 已登记的环境变量

用户已经在 Windows 环境中创建以下变量：

| 供应商 | EvoWeave 读取的变量名 | 厂商文档常用变量名 | 2026-08-13 检查状态 |
|---|---|---|---|
| DeepSeek | `Deepseek_api_key` | `DEEPSEEK_API_KEY` | 当前进程可见 |
| 火山方舟豆包 | `Doubao_api_key` | `ARK_API_KEY` | 当前进程可见 |
| 阿里云百炼千问 | `Qianwen_api_key` | `DASHSCOPE_API_KEY` | 当前进程可见 |

检查过程只判断变量是否为空，没有读取、打印或保存变量值、长度和前后缀。

Windows 在程序启动时复制环境变量。本次三个变量均已被当前进程读取；如果以后修改变量值，已经打开的终端、IDE 或 Agent 进程仍可能无法立即看到新值，需要完全重启相应程序。阿里云官方也明确说明，新设置的 Windows 系统变量不会影响已经打开的程序。[千问 API Key 配置说明](https://help.aliyun.com/zh/model-studio/first-api-call-to-qwen)

### 2.1 变量命名注意事项

- Windows 环境变量通常不区分大小写；Linux 和容器中区分大小写。
- 项目必须严格读取用户已经约定的 `Deepseek_api_key`、`Doubao_api_key` 和 `Qianwen_api_key`。
- 供应商适配器内部可以把它们映射到 SDK 参数，但不要求用户再复制一份官方变量名。
- 不要把变量值写入 `.env.example`、YAML、测试 fixture、日志、异常、Markdown 或 Git。
- 运行容器默认不能获得模型 Key；只有宿主控制平面的 `ModelGateway` 可以读取 Key。

### 2.2 安全的存在性检查

下面的检查只输出“已设置/未设置”，不会输出 Key：

```powershell
$names = @(
    "Deepseek_api_key",
    "Doubao_api_key",
    "Qianwen_api_key"
)

foreach ($name in $names) {
    $present = -not [string]::IsNullOrWhiteSpace(
        [Environment]::GetEnvironmentVariable($name, "Process")
    )
    "$name=" + $(if ($present) { "已设置" } else { "当前进程不可见" })
}
```

禁止使用 `echo $env:Deepseek_api_key` 等命令验证，因为它会把完整密钥输出到终端和工具日志。

## 3. 统一接入设计

### 3.1 统一接口，不统一抹平能力

三家可以共享下面的核心请求概念：

```text
ModelRequest
├─ messages / input
├─ model_profile
├─ tools
├─ structured_output
├─ thinking_mode
├─ timeout
└─ max_output_tokens

ModelResponse
├─ text
├─ tool_calls
├─ usage
├─ finish_reason
├─ provider_request_id
└─ capability_snapshot
```

但供应商差异必须保留：

- DeepSeek 同时提供 OpenAI 和 Anthropic 格式，并有专属 `thinking` 参数；
- 豆包在线推理与 Coding Plan 的 Base URL、模型 ID 和计费体系不同；
- 千问 Base URL 与地域、业务空间和套餐有关，并使用 `enable_thinking` 等扩展参数；
- 结构化输出、视觉、内置工具和上下文长度需要按具体模型确认。

### 3.2 模型选择不能依赖名称猜测

建议维护能力表，而不是使用 `if "pro" in model_name`：

```yaml
provider: deepseek
model_id: deepseek-v4-pro
capabilities:
  chat: true
  tool_calling: true
  json_output: true
  thinking: true
  vision: false
  responses_api: true
```

能力表来源按优先级为：

1. 供应商模型发现接口或控制台实际授权结果；
2. 本项目启动探测；
3. 锁定日期的官方文档快照；
4. 项目默认配置。

若能力未知，系统必须保守降级或拒绝任务，不能因为模型名字相似就推断支持。

## 4. DeepSeek 接入

### 4.1 当前接口

DeepSeek 官方提供 OpenAI 兼容和 Anthropic 兼容接口：

| 协议 | Base URL |
|---|---|
| OpenAI 兼容 | `https://api.deepseek.com` |
| Anthropic 兼容 | `https://api.deepseek.com/anthropic` |

官方当前模型列表为 `deepseek-v4-flash` 和 `deepseek-v4-pro`，并提供 `GET /models` 查询实际可用模型。[DeepSeek 快速开始](https://api-docs.deepseek.com/) [列出模型](https://api-docs.deepseek.com/api/list-models/)

### 4.2 当前相关模型与能力

根据 2026-08-13 官方模型页：

| 模型 | 定位 | 上下文 | 最大输出 | 思考 | JSON | 工具调用 | Responses API |
|---|---|---:|---:|---:|---:|---:|---:|
| `deepseek-v4-pro` | 高质量复杂任务候选 | 1M | 384K | 支持 | 支持 | 支持 | 支持 |
| `deepseek-v4-flash` | 高吞吐、低难度任务候选 | 1M | 384K | 支持 | 支持 | 支持 | 支持 |

两者均支持思考和非思考模式、OpenAI/Anthropic 接口、前缀续写；FIM 仅在非思考模式支持。价格和并发随时间变化，应在运行前查看官方页面，不在项目配置中写死。[DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)

旧模型名 `deepseek-chat` 和 `deepseek-reasoner` 已不是新项目应采用的模型标识。EvoWeave 配置只使用当前 `deepseek-v4-*` 名称，并在启动时通过 `/models` 验证。

### 4.3 Python 调用示例

```python
import os

from openai import OpenAI


api_key = os.getenv("Deepseek_api_key")
if not api_key:
    raise RuntimeError("缺少环境变量 Deepseek_api_key")

client = OpenAI(
    api_key=api_key,
    base_url="https://api.deepseek.com",
)

response = client.chat.completions.create(
    model="deepseek-v4-pro",
    messages=[
        {"role": "system", "content": "返回简洁、可验证的任务分解。"},
        {"role": "user", "content": "分析这个软件变更需求。"},
    ],
    reasoning_effort="high",
    extra_body={"thinking": {"type": "enabled"}},
)

print(response.choices[0].message.content)
```

这是官方 OpenAI 兼容用法对用户变量名的映射。生产代码不得打印完整响应对象，因为响应和元数据可能包含不适合进入日志的上下文。

### 4.4 对 EvoWeave 的用途

- `deepseek-v4-pro`：复杂任务拆分、低置信度根因分析、冲突重新规划；
- `deepseek-v4-flash`：普通 Worker 工具循环、结果归约、批量候选分析；
- Tool Calls：让模型选择 EvoWeave 已授权的原子能力；
- JSON Output：辅助生成 `TaskResult`，但最终仍由 Pydantic 校验；
- 长上下文：可处理较大的上下文包，但不能因此把整个仓库无差别注入。

## 5. 火山方舟豆包接入

### 5.1 必须先区分两类服务

| 服务 | Base URL | 模型 ID 风格 | 计费方式 |
|---|---|---|---|
| 在线推理 | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-seed-2-0-mini-260428` | 通常按量计费 |
| Coding Plan | `https://ark.cn-beijing.volces.com/api/coding/v3` | 点号式套餐模型 ID | 订阅套餐额度 |

两种服务的 Key、Base URL、模型名称和额度不能想当然地混用。项目必须新增非密钥配置 `EVOWEAVE_DOUBAO_SERVICE`，取值只允许 `online` 或 `coding_plan`。如果用户没有选择，程序只做配置检查，不发起付费请求。

火山方舟官方快速开始当前使用 Responses API；EvoWeave 示例沿用官方在线推理 Base URL，但模型改为当前账号已实测的三款之一。[火山方舟快速开始](https://www.volcengine.com/docs/82379/1795150)

### 5.2 与本项目相关的模型

EvoWeave 只保留三款当前账号已完成文本和图片输入实测的在线推理模型：

| 模型 ID | 输入模态 | 上下文 | EvoWeave 用途 |
|---|---|---:|---|
| `doubao-seed-evolving` | 文本、图片、视频 | 1M | 高难度 Agent、长程规划和大型仓库任务 |
| `doubao-seed-2-1-turbo-260628` | 文本、图片、视频 | 256K | 中档能力的普通 Worker |
| `doubao-seed-2-0-mini-260428` | 文本、图片、视频、音频 | 256K | 高频、低难度任务；音频使用前需专项实测 |

Coding Plan 使用另一套点号式模型名称，不能和在线推理的快照 ID 混用。当前账号的 Coding Plan 测试返回 `InvalidSubscription`，因此不进入本项目的三模型基线。[火山方舟 Coding Plan](https://docs.volcengine.com/docs/82379/1925114?lang=zh)

三款的模型目录元数据均声明 Function Calling、JSON Object 和 JSON Schema，并已验证图片输入。平台能力入口还包括深度思考、联网搜索、文件输入和上下文缓存；这些能力仍须按具体端点探测，不能只根据模型族宣传自动启用。[火山方舟产品与能力入口](https://www.volcengine.com/docs/82379/1795150)

### 5.3 在线推理 Python 示例

```python

api_key = os.getenv("Doubao_api_key")
if not api_key:
    raise RuntimeError("缺少环境变量 Doubao_api_key")

    api_key=api_key,
    base_url="https://ark.cn-beijing.volces.com/api/v3",

response = client.responses.create(
    model="doubao-seed-2-1-turbo-260628",
    input="请把这个软件更新需求转换成可验证的任务契约。",
)

print(response.output_text)
```

### 5.4 对 EvoWeave 的用途

- `doubao-seed-evolving`：复杂拆分、设计复核、长程工具循环和大型仓库分析；
- `doubao-seed-2-1-turbo-260628`：普通临时 Agent 和代码分析 Worker；
- `doubao-seed-2-0-mini-260428`：结果归约、分类、快速探测和低风险任务；
- 三款均可读取截图和架构图；视频、音频和 PDF 仍需按任务单独验证。

## 6. 阿里云百炼千问接入

### 6.1 Key 之外还需要地域和业务空间

百炼支持 OpenAI 兼容和 DashScope 两种调用方式。第一版选择 OpenAI 兼容接口。当前官方示例的北京地域 Base URL 为：

```text
https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
```

`WorkspaceId` 必须来自创建该 Key 的百炼业务空间，其他地域 URL 不同。EvoWeave 不应猜测地域，因此需要额外非密钥配置：

```text
EVOWEAVE_QIANWEN_BASE_URL
```

它保存完整 OpenAI 兼容 Base URL，不包含 API Key。只有 `Qianwen_api_key` 而没有正确 Base URL 时，千问 Provider 状态应为“配置不完整”。[千问首次 API 调用](https://help.aliyun.com/zh/model-studio/first-api-call-to-qwen)

### 6.2 当前相关模型与能力

当前官方文本模型页对 Agent/代码场景推荐 `qwen3.7-plus`，强调其 1M 上下文和完整工具调用能力；最高能力候选为 `qwen3.8-max`，低档高吞吐候选为 `qwen3.7-flash`。[千问文本模型选择](https://help.aliyun.com/zh/model-studio/text-generation-model)

| 模型 | 上下文 | 思考 | Function Calling | 内置工具 | 结构化输出 | EvoWeave 候选用途 |
|---|---:|---:|---:|---:|---:|---|
| `qwen3.8-max` | 1M | 支持 | 支持 | 支持 | 支持 | 高难度总调度和复杂分析 |
| `qwen3.7-plus` | 1M | 支持 | 支持 | 支持 | 支持 | 默认平衡模型候选 |
| `qwen3.7-flash` | 1M | 支持 | 支持 | 支持 | 支持 | 低难度临时任务 |

`qwen3.8-max` 当前按量 API 已实测成功；`qwen3.7-plus` 和 `qwen3.7-flash` 除文本外还完成了图片输入实测。专项 Coder、VL、Omni、图像生成和语音模型不进入本项目的三模型基线，只有任务明确需要时才通过运行时模型发现功能临时选择。

### 6.3 Python 调用示例

```python
import os

from openai import OpenAI


api_key = os.getenv("Qianwen_api_key")
base_url = os.getenv("EVOWEAVE_QIANWEN_BASE_URL")
if not api_key:
    raise RuntimeError("缺少环境变量 Qianwen_api_key")
if not base_url:
    raise RuntimeError("缺少非密钥配置 EVOWEAVE_QIANWEN_BASE_URL")

client = OpenAI(
    api_key=api_key,
    base_url=base_url,
)

response = client.chat.completions.create(
    model="qwen3.7-plus",
    messages=[
        {"role": "user", "content": "为这个补丁生成 JSON 格式的风险清单。"}
    ],
    extra_body={"enable_thinking": True},
)

print(response.choices[0].message.content)
```

千问结构化输出可以通过 `response_format={"type": "json_object"}` 启用，但官方要求提示词中出现 JSON，并建议在下游继续做 Schema 校验。[千问结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)

### 6.4 对 EvoWeave 的用途

- `qwen3.8-max`：高难度规划、架构推演、低置信度任务；
- `qwen3.7-plus`：长代码上下文、工具调用和通用 Worker；
- `qwen3.7-flash`：归约、分类和简单任务；
- Plus 和 Flash：截图、界面、架构图和视频需求理解；
- 内置联网、代码解释器等工具默认不接入核心 Worker，避免绕过 EvoWeave 自己的权限和审计层。

## 7. 模型能力如何映射到动态 Agent

EvoWeave 不按固定角色绑定模型，而按任务所需能力动态选择：

```text
TaskSpec
  ↓ 提取所需能力
ModelRequirement
  ├─ reasoning_level
  ├─ tool_calling
  ├─ structured_output
  ├─ context_window
  ├─ vision
  └─ latency_class
  ↓
ModelRouter
  ↓ 从已探测模型中选择
Provider + Model ID + Parameters
```

示例：

| 任务 | 需要的模型能力 | 不应自动获得的能力 |
|---|---|---|
| 只读影响分析 | 中高推理、长上下文、工具调用 | 写文件、网络搜索 |
| 小范围代码修改 | 代码能力、工具调用、结构化结果 | 越界目录、主分支写入 |
| 结果归约 | 低难度、短上下文、JSON | 终端和文件写入 |
| 高风险补丁复核 | 强推理、长上下文 | 修改被复核补丁 |

模型具备 Function Calling 只表示它能生成工具调用意图，不表示它有权执行工具。实际工具必须经过 `AgentExecutionSpec` 和权限策略校验。

## 8. 启动探测和实际可用模型

“官网支持某模型”不等于当前 Key、地域和套餐已经授权。正式实现应提供只读命令：

```text
evoweave models doctor
```

它应执行：

1. 只检查 Key 是否存在，不打印 Key；
2. 校验 Base URL 和服务类型是否完整；
3. 调用供应商模型列表接口（若提供）；
4. 对用户选中的模型执行最小能力探测；
5. 记录模型 ID、端点、响应能力和检查时间；
6. 不自动发起大上下文、长输出或多轮付费测试；
7. 若探测可能产生费用，必须明确提示并由用户确认。

### 8.1 2026-08-13 真实连通性与多模态测试

经用户明确要求，本次使用三把 Key 执行同一个最小问答：`只回答一个数字：7乘以6等于多少？`。测试脚本只输出模型、HTTP 状态、答案、Token 用量或脱敏错误码，没有打印、保存 API Key 或 Authorization Header。

| 供应商 | 端点与模型 | 结果 | 调用证据 | 当前判断 |
|---|---|---|---|---|
| DeepSeek | `https://api.deepseek.com/chat/completions`；`deepseek-v4-flash` | 成功 | HTTP 200；答案 `42`；输入 94、输出 14、合计 108 Token，其中推理 12 Token | Key、端点和模型均可用 |
| 火山方舟豆包 | `doubao-seed-evolving` | 成功 | 文本 HTTP 200、答案 `42`；图片 HTTP 200、识别 `42` | 文本和图片可用 |
| 火山方舟豆包 | `doubao-seed-2-1-turbo-260628` | 成功 | 文本 HTTP 200、答案 `42`；图片 HTTP 200、识别 `42` | 文本和图片可用 |
| 火山方舟豆包 | `doubao-seed-2-0-mini-260428` | 成功 | 文本 HTTP 200、答案 `42`；图片 HTTP 200、识别 `42` | 文本和图片可用；音频未实测 |
| 阿里云百炼千问 | `qwen3.8-max` | 成功 | 文本 HTTP 200；答案 `42` | 文本可用 |
| 阿里云百炼千问 | `qwen3.7-plus` | 成功 | 文本 HTTP 200、答案 `42`；图片 HTTP 200、识别 `42` | 文本和图片可用 |
| 阿里云百炼千问 | `qwen3.7-flash` | 成功 | 文本 HTTP 200、答案 `42`；图片 HTTP 200、识别 `42` | 文本和图片可用 |

豆包目录中列出模型仍不等于账号已开通推理权限。本轮筛选中，其他 Pro、Lite 和 Code Preview 候选均返回 `ModelNotOpen`，因此不记录其精确 ID，也不进入最终三模型基线；Coding Plan 仍返回 `InvalidSubscription`。

## 9. 失败切换和可复现性

### 9.1 不能静默切换模型

如果首选模型不可用，系统只能：

- 在任务允许的候选 Profile 中选择能力不低于要求的模型；
- 记录切换原因、原模型和新模型；
- 重新校验输入模态、上下文和能力硬约束；
- 高风险任务要求人工确认。

不能在 404、429 或余额不足时静默切换到能力不满足要求的模型，也不能丢弃图片后改用纯文本模型，因为这会破坏实验可复现性和结果质量边界。

### 9.2 每次运行必须记录

- 供应商；
- Base URL 的非敏感标识；
- 模型 ID 和快照名（若响应提供）；
- 思考模式和关键参数；
- 输入、输出和缓存 Token；
- 时延、重试和错误码；
- 工具调用能力和结构化输出能力；
- 路由原因和失败切换记录。

任何日志都不得包含 API Key、Authorization Header 或未脱敏的敏感仓库内容。

## 10. 实现顺序

模型接入仍按离线优先原则分阶段：

1. 定义 `ModelRequest`、`ModelResponse`、`ModelCapabilities` 和 `ModelGateway`；
2. 实现不联网的 `FakeModelGateway`，完成协议、状态机和权限测试；
3. 实现环境变量存在性与非密钥配置检查；
4. 实现 DeepSeek、豆包、千问三个适配器；
5. 添加模型发现与最小探测命令；
6. 用户确认真实模型调用后执行连通性和能力测试；
7. 用固定基准任务决定默认模型 Profile。

在第 6 步之前，核心测试不需要三个 Key；真实模型测试与核心 CI 分离。
