# 多模块并行更新示例

目标：允许总调度根据仓库证据把需求拆成多个独立写集合。阶段 6 CLI 已连接动态图控制面：显式路径、目录代码规模和 Python import 关系共同决定任务数与依赖；互不冲突的首批任务会获得独立 Agent 和 worktree 并发运行。

```powershell
evoweave run C:\path\to\repo `
  --request "同时更新订单价格计算与对应测试" `
  --path src/shop/pricing.py `
  --path tests/test_pricing.py `
  --execute --trusted-host-validation --json
```

运行会固定 base commit、候选影响范围、难度和模型需求。两个任务只有在依赖和实际写集合允许时才会并行；如果测试任务依赖源码任务，则 DAG 会把它放到后续批次。难度影响模型能力档位，但不会直接决定 Agent 数量。
